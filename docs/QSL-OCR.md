# Local QSL image OCR

From an existing QSO's **Received QSL archive**, open **Read image with local OCR**, select a local image and choose **Read image**. The application starts a separately installed Tesseract executable locally with the English (`eng`) language model and reads its TSV output. It searches the process PATH and, on macOS, `/opt/homebrew/bin` and `/usr/local/bin`. Tesseract and its model are not bundled; install them separately from a trusted source and make the executable available to the desktop app. The [upstream command-line documentation](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html) describes the TSV interface and [Tesseract's source is Apache-2.0 licensed](https://github.com/tesseract-ocr/tesseract/blob/main/LICENSE); its dependencies and model data have their own distribution requirements.

The display shows raw text and words below a heuristic 75/100 confidence threshold, not calibrated probabilities. Review every character against the original image, including words above the threshold. The OCR result does not update a QSO, create a contact, attach an image, or grant QSL/award credit. Use the existing **Import scan or image** action separately to attach the original to the selected QSO. File selection does not upload the image. The selected file is copied asynchronously to a private temporary directory and the local engine reads that copy. Its SHA-256 identifies the bytes processed; do not change the source while the copy is being made. The temporary copy is removed on the next OCR attempt or normal application exit, but an abnormal termination can leave temporary files behind. OCR results are held in memory and disappear when the app exits. The existing separate attachment action reads the file selected at attachment time, so it does not yet guarantee that it attaches this OCR snapshot.

The reader proposes possible callsigns, dates, times, bands and modes from recognisable whole words. These are not validated facts; other text can resemble a callsign and values can be missing. A date such as `03/04/2026` yields both valid interpretations marked with `?`, rather than choosing a locale. Compact times are suggested only next to TIME or UTC; unlabelled numeric values are not inferred. Each suggestion category is capped at 100, with an omission warning. Select a proposed callsign and request an exact-call search to see up to 100 recent-by-ID, non-deleted log records; a warning appears if more exist. This asynchronous search uses a separate read-only database connection, can be cancelled and does not filter by date, time, band or mode. Results can become stale as the log changes; compare all details with the card. It does not claim a match, update records or attach the image.

This initial implementation accepts locally readable images up to 32 MB and 40 million pixels, with each dimension at most 12,000 pixels. PDF OCR, language selection, reliable structured extraction, date/time-aware candidate ranking, multi-QSO review, persistent acquisition and undo are not yet implemented. Cancel stops the local process; a 90-second limit and 4 MiB result limit bound a run. Errors are reported without retaining OCR output. Engine installation, language data and platform packaging need separate verification on Windows and Linux. Two synthetic printed layouts are not evidence of handwriting, faded cards or arbitrary QSL quality.
