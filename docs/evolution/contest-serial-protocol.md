# Experimental contest serial message contract

This is an experimental contract with an opt-in authority receiver in ContestNet. The existing `serialreq`/`serialgrant` flow remains volatile and is not made reliable by this document.

An operator or future session configuration must explicitly choose one scope and one authority node. The protocol does not elect a replacement authority and does not allocate locally when that authority is unavailable. Separate authority databases can allocate the same number; do not run two authorities for one scope.

The requester first persists a `pending` request with scope, requester ID, request ID, authority ID and minimum. An experimental `serial_request_v3` frame carries those fields and `serialProtocol: 1` inside the existing `DXLNET` envelope. A retry must reuse the same request ID and parameters. The authority checks the configured scope, its own ID and the envelope's requester ID, then commits a reservation before returning a `serial_grant_v3` frame containing the same fields plus `serial`. A duplicate request returns the persisted number. A reused request ID with a different minimum is rejected.

The requester checks the configured scope and authority, the envelope sender, all recorded request fields and the positive integer serial before committing the grant. Duplicate identical grants are idempotent; conflicting grants are rejected. A database API can insert a QSO and bind the granted serial to its UUID in one transaction, refusing a conflicting STX or an already-consumed grant. This API is not yet used by the QSO entry workflow and is not proof that a number was transmitted. The separate generic use-ID operation remains available. Never silently renumber a transmitted number.

The station network panel exposes experimental, in-memory scope and authority configuration; it is disabled again on restart. Only the named local authority serves requests. The authority opens a separate database connection on a worker and responds only after committing the reservation; one request or grant is processed at a time, and packets arriving while busy are dropped. The requester persists a request before sending and retries it every two seconds using the same authority and minimum until a grant is recorded. The retry timer stops if configuration, network or open-log identity changes. Following a process restart, the operator must reconfigure and request again to resume the saved pending request. A matching grant is displayed as experimental; QSO entry is not connected. A configuration or network restart suppresses a completed worker's notification or response; an already committed request, reservation or grant remains in its originating database. File identity checks reduce accidental log replacement but are not atomic with every filesystem race.

ContestNet UDP sender IDs are unauthenticated and may be spoofed. These checks prevent accidental misrouting, not hostile impersonation. This contract has not been negotiated with older clients and does not resolve split-brain authority. See `PROGRESS.md` for actual test evidence and outstanding LAN, restart, partition and interoperability work.
