## 2026-11-22 — G01/G05 import transaction integrity

Before: failed SQLite commit was ignored and the report included uncommitted IDs. A synthetic deferred-foreign-key fault reproduced `inserted=1` despite failed commit. Separately, a QSL-write failure returned an error but left an unreported QSO in the batch; A/B fault injection reproduced `qsoCount=1` instead of 0.

After: imports require their own batch transaction and stop explicitly if it cannot start; failed commits roll back the current batch, remove its IDs and inserted/duplicate counts from the report, preserve previously committed batches, and report an error. A per-record savepoint rolls back partial QSO/QSL writes; failure of savepoint handling rolls back the batch. The controller marks reports containing errors as warnings. Per-record savepoints add overhead; large-log A/B latency measurements are still required. Read/missing-UTC/QSL counts refer to attempted records, including a batch whose commit failed; they are not committed-row counts.

Synthetic tests exercise commit rejection, retry and reopen of a file-backed log; a later batch failure with an independently inserted QSO between batches; refusal of an already active transaction; and QSL write failure. A/B failures above pass after the fix. `cmake --build /tmp/decolog-evolution-build --target tst_database tst_migration decolog -j 4` succeeded; `QT_QPA_PLATFORM=offscreen ctest --test-dir /tmp/decolog-evolution-build -R '^(database|migration|qmlpopups)$' --output-on-failure` passed 3/3 on macOS arm64 / Qt 6.11.2. Fault injection is local, not a live database crash or hardware test. No schema migration. The work does not implement persistent import undo: the in-memory ID list, partial undo recovery and cross-log identity remain open. ## 2026-11-22 — G05 durable import journal foundation

Schema 12 adds `import_batch` and `import_qso`. For imports with source `import`, each newly inserted QSO is journalled with the batch UUID, local ID, persistent QSO UUID and insertion revision inside the same per-item savepoint and batch transaction. Preview imports and independent radio QSO are not journalled. A journal-write failure rolls back the corresponding QSO; a rejected batch commit leaves no journal entries from that batch, while earlier committed batches remain recorded. Empty or duplicate-only imports create no new journal batch. This is a foundation: no user-facing persistent undo, recovery of old imports, or proof of safety for edited/QSL-modified records is provided yet.

A/B: before schema change the file-backed restart fixture failed with `no such table: import_qso`; after, it finds the correct imported QSO UUID/revision and excludes a later independent QSO. Additional synthetic tests inject failure into the journal, reject a later batch commit, and reopen a simulated schema-11 database containing a QSO: version advances to 12 and ID/UUID/data remain. Existing older-schema migration tests also pass. `cmake --build /tmp/decolog-evolution-build --target tst_database tst_migration decolog -j 4` and `QT_QPA_PLATFORM=offscreen ctest --test-dir /tmp/decolog-evolution-build -R '^(database|migration|qmlpopups)$' --output-on-failure` passed on macOS arm64 / Apple M4 / Qt 6.11.2. Simulated v11 was created by removing the new tables and version marker from a fresh database; it is not a captured customer log. The v12 migration is transactional; downgrade is not supported as a tested procedure, so use a verified pre-upgrade backup to return to an earlier application.

Performance A/B: alternating six subprocess runs each of `tst_database aSelectionExportsLikeTheWholeLog` on the same machine, Release build, offscreen, in-memory SQLite, 1,203 synthetic QSO plus full and selection ADIF exports. Before transaction fix `e6e9ba3`: 307.4, 102.1, 102.1, 102.6, 101.7, 100.7 ms (median 102.1); transaction fix `f54300c`: 190.3, 108.7, 109.0, 108.6, 108.5, 107.1 ms (median 108.6). A separate alternating run comparing `f54300c` with schema-12 journal: 109.4, 107.2, 108.5, 108.8, 107.2, 107.5 ms (median 108.0) versus 122.2, 122.2, 121.8, 121.9, 124.5, 120.8 ms (median 122.0). These include process startup, import and export, not UI latency, isolated import timing or large-log throughput. Outliers and the difference between runs limit interpretation; measure p50/p95 and concurrent logging on representative larger, file-backed datasets before acceptance.
