# Decisions

- Preserve existing award and import models; add evidence and contracts incrementally. A confirmed QSO is not automatically an official award credit.
- The web contest calculation remains the existing generic model while explicitly labelled as an estimate. Shared official scoring remains open; no scoring semantics changed.
- Marathon edition matching uses UTC for all timestamp representations; database loading already converts to UTC. This prevents equivalent instants receiving different edition decisions.
- Synthetic fixtures and real exports, simulated peers and real hardware, local build and packaged releases must be recorded separately. No mobile development.
- Keep the legacy Marathon `selected` entity array and add a separate `zoneCandidates` array so existing consumers retain their entity-selection contract. Candidates are explicitly unverified; a numeric CQ zone range is not proof of a valid program entry or location.
- Require an explicit station profile for Marathon preview in the desktop UI, while preserving the selector's existing all-profiles API for other callers. This avoids silently combining profiles, but is not evidence that a profile contains one operating location. Use atomic replacement for the internal JSON export.
- Import batches must own their transaction; refusal is explicit if one is already active. Each QSO insertion uses a savepoint so a failed QSL subwrite cannot commit an unreported QSO. Committed prior batches remain available after a later failure; import progress is emitted only for committed batches. Measure savepoint overhead on representative logs.
- Schema 12 journals successfully inserted `source=import` QSO in the same transaction as their creation, retaining persistent UUID and revision alongside the local ID. The journal does not retroactively describe previous imports. The migration is additive and transactional; restoring an earlier version requires a verified pre-upgrade backup because downgrade is untested. The journal is a prerequisite, not proof that undo is safe or available.
- Schema 13 retains an import-time fingerprint covering the QSO row, QSL service state, attachment metadata and enrichments. Undo checks local ID, UUID, revision and fingerprint inside a transaction before soft deletion; incomplete legacy baselines fail closed. This intentionally favours review over deleting a changed QSO. Do not run this synchronous core loop on the UI thread for large imports; optimise and measure fingerprint cost.
- Run import undo on the import worker pool with its own SQLite connection. Cancellation is cooperative between QSO transactions; completed soft deletions are retained and retries remain idempotent. Require explicit UI confirmation; a generic warning is not a replacement for the still-pending per-QSO review.
- Reuse prepared fingerprint and journal queries within a single owning `LogDatabase` operation, preserving the existing schema-13 fingerprint bytes. Statements are not shared across worker threads. Prepared-query reuse reduces but does not eliminate the measured overhead; the representation must be explicitly versioned or preserved when QSO columns change.
- Report per-record undo exclusions after processing, with a bounded first 200 issues and explicit omitted count; do not show the callsign of a different QSO occupying a stale ID. This is not yet a pre-operation or exhaustive review. Recheck identity and baseline during each mutation even when a future preview is added.
- Preview undo asynchronously and bind confirmation to both the current log path and the reviewed import batch's ID and UUID. Treat per-record preview totals as advisory because the log can change; recheck identity and fingerprint in each deletion transaction. A legacy no-argument controller invocation retains its previous latest-batch semantics, while the desktop confirmation requires the reviewed identity.
- Bound undo/preview journal reads to keyset pages of 128 entries, with an initial cancellation point and an indexed `(batch_id,qso_id,qso_uuid)` order in schema 14. The initial count and maximum ID bound the scan but do not guarantee a stable membership snapshot under external writers; do not present them as one.
- Schema 15 uses transactional SQLite triggers to increment a batch journal revision on each insert/update/delete. The desktop preview token includes batch ID, UUID and revision; the worker rechecks membership inside each QSO transaction and at scan end. A mismatch stops safely but does not roll back earlier committed QSO deletions. Triggered membership stability does not imply a coherent snapshot of QSO data.
- G08 uses a radio-net session and roster stored in the current log (schema 16), independent of ContestNet. Check-ins append history but never create QSO or issue radio commands. This initial local workflow does not claim Cloud synchronisation, session export or full operational acceptance.

- G08 export streams the complete selected session from a worker-owned SQLite read transaction to an atomically replaced local JSON file. A participant may explicitly open a prefilled QSO draft; roster actions never save a QSO and an existing radio-net draft is not overwritten. The export format is application-specific and saved QSO association is not yet implemented.

- G08 history uses indexed descending event IDs as page boundaries, fetching at most 201 rows to show 200 and determine whether older events exist. New events appear when the newest page is revisited; browsing is not a frozen snapshot.

- G08 optional reminders store a UTC deadline or cancellation as session history, without a schema migration. The countdown is visual in the selected manager window; no background or operating-system alert is claimed.

- G09 manual QSO entry exposes distinct RX frequency alongside the satellite fields and validates positive finite RX MHz. When explicitly supplied, the regular frequency is the TX frequency; existing automatic split handling remains for a blank RX. This is data entry, not an orbital tracker or CAT ownership mechanism.

- G09 PREDICT UDP snapshot client is read-only, requires a numeric IP address, and verifies tracking mode both before and after the sample. A TLE epoch is exposed separately; the snapshot does not itself prove accurate orbital data or a continuously updating server. The core is not yet wired into desktop workflows.

- G09 PREDICT pass requests accept a strict ASCII satellite-name allowlist because upstream PREDICT 2.2.x invokes a shell. Pass streams are bounded and require ordered points, plausible horizon endpoints and unchanged TLE; these checks cannot guarantee UDP completeness and may reject slow passes.

- G09 preview scales PREDICT normalized 100 MHz Doppler by the user-entered nominal downlink, and applies the opposite sign to nominal uplink; it never tunes. An explicit draft requires a local reading at most 10 seconds old and a non-future TLE at most 14 days old. These bounds are cautionary and do not establish orbital or frequency correctness.

- G02 VUCC preview expands only reported two/four adjacent 4- or 6-character VUCC_GRIDS into unique GRID4 candidates; malformed or inconsistent reports are excluded. MY_VUCC_GRIDS is preserved as reported provenance, not validated as an operating site or award eligibility. Official rules remain unverified.

- G09 rover stores a separate local session and position history. Only explicit manual QSO entry may inherit a position from an active session with the same station profile; distinct positions in one minute, concurrent activation or a mismatched profile require an explicit own grid. Existing QSO are not rewritten. Position precision is one minute, a backward clock rejects new positions, and cross-process attribution is not guaranteed.

- G08 explicit radio-net QSO drafts capture the session and member; saving requires the same call and an open session. The session UUID and member call are stored in QSO ADIF extras in the same QSO insertion, rather than inferred from roster participation. These fields are reported metadata, not a foreign key or proof that an imported QSO belongs to a local session; concurrent cross-process changes are not serialized with insertion.

- G08 session QSO browsing and JSON export match the reported session UUID stored in QSO ADIF extras, and label the results as reported metadata. The member call and source remain visible; imported data and later edits are not proof of participation. Schema 18 adds a partial expression index; malformed extras are skipped and a legacy schema lacking the indexed columns skips the index.

- G12 local OCR uses an optional separately installed Tesseract executable and English model; it is started without a shell for an operator-selected local image. Results and heuristic word scores are temporary suggestions and never alter QSO or confirmation state. Image attachment remains a separate explicit existing action, so the operator must ensure the attached file is the intended original.

- G12 OCR field suggestions are heuristics, never auto-applied. Ambiguous numeric dates retain both valid interpretations and each suggestion keeps its raw word; exact-call candidate lookup is opt-in, bounded to 100, read-only, asynchronous and cancellable. It does not automatically filter by time, date, band or mode, and a candidate is not a confirmed correspondence.

- G12 OCR processes a bounded, SHA-256-labelled temporary copy made asynchronously; later changes to the original cannot alter the bytes fed to Tesseract. The existing separate attachment action does not consume that snapshot and therefore does not yet establish provenance between OCR and attachment. Normal cleanup removes the copy, but crash cleanup is not guaranteed.

- G12 explicit OCR approval records the verified image snapshot, recognized text and selected QSO identity/revision in schema 19. Existing identical attachments and links are reused; new links and the journal are committed atomically only if every selected QSO still has its searched UUID and revision. An acquisition is not an award or QSL confirmation. Cancellation is honoured before commit; journal review and safe undo are not yet implemented.

- G12 schema 20 tags links created by OCR acquisition with a unique token and revision. Current normal attachment and later OCR reuse increment link revision. History and undo are asynchronous; guarded undo checks the original acquisition UUID, every created link token/revision and QSO UUID/revision under one write transaction, or changes nothing. The blob and journal remain. Schema-19 acquisitions with untracked created links are review-only. Older clients or direct SQL can bypass link-reuse tracking.
