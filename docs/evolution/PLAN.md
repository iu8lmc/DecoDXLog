# Desktop evolution plan

Scope: desktop Windows, macOS and Linux, and the existing cloud; no mobile client. The eleven product streams remain in scope. This is a working status summary, not acceptance of any goal; the detailed, dated evidence and superseding changes are in [PROGRESS.md](PROGRESS.md).

| Goal | Dependencies | Current slices / next verifiable work |
|---|---|---|
| G00 Baseline | checkout | Starting checkout, initial build and partial code assessment recorded in BASELINE; continue revalidating each stream and its proof against the evolving code. |
| G01 Reliability | G00 | In progress: import recovery and bounded bulk operations are implemented; local A/B tests found and corrected SQLite contention during 20,000-QSO field, tag and deletion operations with one concurrent UDP QSO. Reproduce the Windows issue and verify sustained traffic, other writers, slow storage and other platforms; see PROGRESS for the tested boundaries. |
| G02 Awards | G00, G01 | Partial: VUCC preview handles adjacent reported multiple grids and preserves own-grid metadata; verify source eligibility, official rules and geographic/account constraints. Marathon work remains open. |
| G03 QSL planner | G02 | Partial: snapshot-based review uses configured award rules, guarded paper handoff and scoped goals. It groups recorded paper routes and pending electronic confirmations, and separately shows service-based potential benefits with station participation explicitly unverified. Complete electronic service verification, cost verification, broader queue/email/OQRS integration and cross-platform/concurrency checks. |
| G04 DX campaigns | G02 | Partial: local per-log campaigns have editable period/profile matrices, manual calendar date review, per-cell objectives, goal-aware spots and opt-in alerts. Paged campaign history can load a prior revision as a reviewable draft for explicit saving as a new revision; revisions from before history was introduced cannot be recovered. Stable event linkage, restore provenance/retention policy, richer alerts, sync and operational verification remain. |
| G05 Migration and sync history | G01 | Partial: import preview and persistent batch journal, guarded background undo and issue review are present; confirmation summaries distinguish ambiguity, invalid data and database errors. Complete source-specific interoperability with real exports, durable reconciliation, concurrency/crash and large-log verification. |
| G06 Multi-program activation | G02, G05 | Partial: independent references, tracked session history, local POTA/SOTA catalogues, programme-specific preview and partitioned ADIF export are present. Validate official eligibility/imports, operating periods, large review sets and cross-platform behavior. |
| G07 Typed fields and reports | G01, G02 | Partial: New QSO custom ADIF fields support typed definitions, units, simple conditional requiredness and bounded arithmetic formulas with dependency/cycle checks and per-QSO input provenance; QSO detail warns about stale results and offers explicit previewed recalculation using recorded formulas. Fixed examples and a configurable one-to-three-dimension QSO/distinct-call report run asynchronously with named per-log definitions and CSV/PDF export. Richer rules, atomic concurrent editing, other entry/import paths and richer aggregation/filtering remain. |
| G08 Radio net manager | G01 | Local roster, session persistence, statuses, order, turns, paginated history UI, status/check-in summary, persisted visual reminder including a main-window due banner across active sessions in the current log, explicit QSO draft and complete JSON export implemented. An explicit participant editor changes or clears name/notes with stale-value rejection and a history event. Explicitly saved QSO carry session UUID and participant call; reported QSO are paginated and included in session JSON. Complete stronger association guarantees, broader reminder notification and operational verification. |
| G09 Satellite and rover | G02, G06, G11 contracts | Partial: manual entry stores distinct TX/RX; read-only PREDICT desktop snapshots and optional repeated refresh implemented. Next/following pass prediction and a bounded schedule with sampled-elevation filtering are available through PREDICT; local rover session and manual-QSO position history implemented; a separate read-only tracker status adapter consumes API snapshots with freshness flags; complete pass planning, automatic workflows, wider rover integration and operational verification remain. |
| G10 Contest | G01, G05 | Partial: existing rules, SO2R, ContestNet, call queue, session audio, CQ WW report review and post-contest comparison slices exist. Experimental persistent requester/authority grants are connected to the network and explicit QSO entry, with warnings about unauthenticated peers and multiple authorities; the older volatile path remains. Multiplier handoff/skeds, full contest-rule coverage, distributed fencing/convergence, real LAN/SO2R and complete operational verification remain. |
| G11 SDK | G01 | Partial: the local API has shared keys and manually managed scoped credentials; Setup creates and revokes keys, and the experimental manager checks credentials against manifests. A standalone report, read-only tracker example and developer harness exist. The transactional QSO event journal provides bounded retention and scoped paged HTTP reads; an example managed counter supports replay-safe local state and explicit, recorded gap acceptance. Missing events are not restored and external side effects are not atomically acknowledged. Automatic credential provisioning/revocation, broader reliable consumption, durable atomic API idempotency, managed process isolation and a fully managed tracker adapter remain. |
| G12 OCR and historical logs | G05, G07 | Partial: local Tesseract OCR displays raw text and heuristic suggestions; asynchronous exact-call search accepts optional explicit UTC date/time and manual corrections; approval attaches the verified OCR copy to selected QSO and journals provenance; versioned reviewed transcriptions have paged read-only history, and guarded undo preserves prior or later-reused links; historical manual entry provides UTC rollover and optional profile use. Robust extraction and broader operational verification remain. |
| G13 Integrated desktop acceptance | all | In progress: local packaged-app smoke and migration fixtures and the separately published v1.17.67 are recorded. The full integrated workflow, clean installations and real platform, service and hardware checks remain required. |
