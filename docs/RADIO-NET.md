# Radio net manager (desktop, initial implementation)

Open **Radio net manager** from the main menu. Enter a session name and choose **Start session**; the active station profile is stored with it. Check in a callsign with optional name and notes. Re-entering the same callsign in the same session returns it to present rather than creating a second participant. An empty name or note on re-entry retains the existing value. Use the status selector for present, waiting, absent or departed, the arrows to change call order, and **Next turn** to advance among present and waiting participants. Close and reopen a selected session as needed. The session, order and event history are stored in the current log and reload on restart. The summary shows unique participants, current status totals and the number of check-ins, including returns.

A roster entry does not create or transmit a QSO. Choose **New QSO…** beside a participant to open the normal QSO entry window with the callsign and name prefilled. Saving remains an explicit operator action. An already open radio-net QSO draft is preserved instead of being replaced. The saved QSO is not yet linked to the session.

**Export JSON…** writes the selected session, participants and complete event history as a local `decodxlog-radio-net-1` JSON file. Export runs on a separate database connection using a read transaction and atomic file replacement; it can be cancelled. The open log and its SQLite sidecars cannot be selected as the destination. The history window displays up to 200 events per page; use **Older** and **Newer** to navigate the full history. New events are shown when returning to the newest page. This format is specific to DecoDXLog; interoperability with other tools has not been established.

Set an optional reminder in seconds (1–86400) for the selected active session. The countdown and a visual **Reminder due** message appear in the Radio net manager; clear it explicitly or set a new deadline. The UTC deadline and its cancellation are saved in the session history and survive restart, including expiry while the application was closed. This visual reminder does not currently issue a sound or operating-system notification and is visible only while the manager shows that session. Clock changes affect the deadline. Sessions and roster are local to the log; cloud synchronisation and concurrent live refresh between different application instances are not established.

Schema 16 adds the local session, member and event tables in a transaction. Keep a verified backup before upgrading; downgrade to an older application has not been tested. See `docs/evolution/PROGRESS.md` for test evidence and remaining work.
