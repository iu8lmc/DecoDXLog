# ContestNet QSO convergence foundations

The existing ContestNet QSO path remains the legacy UDP path. The schema-28/29 change journal and `ContestNetInventory` are local foundations and do not currently transmit or apply QSO revisions.

An inventory opens an existing schema-29-or-newer file read-only and starts one SQLite read transaction. Schema 29 is required because schema 28 does not journal QSL-only changes. Its log identity and journal watermark are obtained from that snapshot; pages enumerate QSO ID, UUID, revision, soft-deleted state, a content fingerprint and a UTF-8 ADIF record in ID order, including pre-migration records and tombstones. Pages are limited to 500 rows and a configurable returned-payload budget (default 1 MiB, maximum 16 MiB). If a single next record exceeds that budget, the call reports an error without advancing the cursor; the caller can retry with a larger permitted budget. The limit covers returned ADIF bytes, not all temporary SQLite and string allocations. Each payload is parsed again using this application's ADIF parser and must reproduce the fingerprint, or the page fails without partial results. Closing or destroying the inventory releases the transaction. The object and its SQLite connection must remain on their creating thread.

A future reconciliation can compare that inventory, then inspect journal entries after its watermark. The fingerprint is SHA-256 of a version-tagged Qt 6.0 `QDataStream` in big-endian format: a field count followed by ADIF field names sorted lexically and their exact values. It covers fields returned by `recordChecked`, including ADIF-visible QSL state; it does not include QSO UUID, revision, attachments, station-profile records, local QSL remote IDs or other non-ADIF metadata. It is a candidate comparison aid, not proof of semantic equivalence: different formatting can produce different fingerprints and a cryptographic collision is theoretically possible. A failed QSO or QSL query or malformed/non-string ADIF extra data aborts the page rather than hashing missing data. The current implementation performs separate QSO and QSL queries per row; it requires realistic large-log performance testing before use in an interactive workflow.

Journal entries are only local metadata; there is no peer acknowledgement, ordering contract, conflict policy, checkpoint or implemented replay. The inventory ADIF payload may contain private QSO notes and QSL fields, and is not sent over the network by this increment. A record exceeding the maximum budget requires a separate future large-record transport; no fragmentation is implemented. Round-trip validation uses this application's parser and does not establish interoperability with another ADIF implementation. Schema 29 journals QSL inserts, removals and changes to ADIF-relevant status fields, including changes which do not increment the QSO revision; changes only to local remote ID or error text do not create entries. A QSL move between QSO records both identities. Entries may be conservative duplicates and do not contain snapshots. Arbitrary raw SQL changes to QSO content without a revision/identity/deletion change, physical QSO deletion and non-ADIF data are still not covered. UUID adoption and Cloud revision updates can generate entries, and a QSO revision is not necessarily monotonic across Cloud operations. The sequence and log identity cannot prove continuity across a restored or copied database without additional binding and validation.

The inventory checks the file identity captured on open before and after each page, and stops if the path is replaced. Capturing the token from the path after opening SQLite is not atomic with the SQLite open; in-place changes, file-ID reuse and network-filesystem semantics are not covered. Keep read transactions brief: in WAL mode a long snapshot can retain WAL pages, while rollback-journal mode can block writers. The current API has no asynchronous UI integration, automatic deadline or resumable snapshot after process restart.

`ContestNetReconcile` compares two local, independently pinned inventories in SQLite binary UUID order with bounded internal pages. It reports local-only, remote-only, matching fingerprint, revision difference with matching fingerprint, content conflict, or deletion-state conflict. It does not infer that a higher revision wins, automatically merge QSLs, match different UUIDs by callsign/time, change either database, or send data to a peer. A matching fingerprint covers only the documented ADIF projection and does not imply that attachments or other local metadata match. The two snapshots are opened sequentially and have separate watermarks; changes after either snapshot require a future catch-up protocol. Callers must discard the entire comparison if a later page fails, including any earlier pages, and close the snapshots promptly. A configurable per-source payload budget is capped at 16 MiB; an oversized first record aborts comparison rather than skipping it. File identity checks also cover rows buffered between pages, subject to the filesystem limitations above.

The station-network panel offers a read-only offline comparison against a user-selected local log file. It runs on a worker, counts all classifications, and shows the first 200 differences with QSO summaries. Where both records exist and their ADIF fingerprints differ, it also lists up to 32 differing ADIF fields with values from each side and distinguishes missing fields; additional fields and names or values longer than 256 UTF-16 code units are marked as omitted or truncated. A truncation does not modify the stored value. These previews may contain private QSO notes and QSL data and remain local. They do not include attachments or fields outside the ADIF projection, and the view cannot apply or resolve a conflict. Cancellation is checked between pages. The UI checks the open log and a separate read-only SQLite connection for commits to the selected log, and marks the result stale when either changes or a file is replaced. Polling is periodic, so a result can be briefly stale before the next check; non-SQLite in-place file manipulation and filesystem races are not covered. There is no merge, remote peer protocol or resumable comparison.

See [PROGRESS.md](PROGRESS.md) for the tests actually run and remaining LAN, conflict and cross-platform work.

### Experimental single-record framing

`ContestNetQsoTransfer` defines a version-1 JSON fragment contract around a single inventory ADIF payload, using 512-byte raw chunks, strict metadata and a 4 MiB maximum. A receiver is bound to an expected sender identifier and transfer ID, accepts out-of-order and duplicate fragments, and only releases a record after checking both payload SHA-256 and the existing ADIF fingerprint. These checks detect accidental corruption; sender IDs and hashes are not authentication. The contract is standalone and is not wired to production networking, persistence or QSO application. Callers must impose aggregate transfer limits, deadlines and authorization before exposing it to peers; records above 4 MiB currently cannot be transferred.

After receiving one valid fragment, the experimental receiver can list up to 32 missing indices in a request bound to the transfer ID and payload hash. The encoder validates the complete request before returning frames. Requests are not authenticated, do not discover a wholly lost transfer, and are not sent or retried automatically; the production controller does not use this contract.

An experimental `applyMissing` operation can transactionally insert a fully reassembled non-deleted record into an explicitly identified local file-backed log. It checks the persisted ADIF fingerprint, refuses duplicate or divergent existing records, and does not overwrite existing QSO. The operation is not exposed in the UI or called by the network controller; its caller must establish peer authorization and obtain an explicit review. ADIF-visible fields alone do not include attachments, local service metadata or station-profile assignments.

A separate experimental review token can guard a caller-selected edit or soft deletion of an existing local QSO. It compares the local revision, deleted state and ADIF fingerprint and the received payload again inside the write transaction; local revisions continue independently. This is a primitive for a future operator review, not an automatic conflict policy. The review also guards QSO columns, service metadata, enrichment rows and attachment metadata/link state; it does not hash attachment binary data. It is not connected to UI or networking.

A pinned inventory can also fetch an individual UUID without advancing its page cursor. The lookup returns the same snapshot content and uses the same payload and file-identity guards as pagination; it does not itself authorize or apply a change.

The offline comparison UI can inspect all ADIF fields of a displayed difference using direct UUID lookup in fresh pinned snapshots, guarded against observed log changes. This remains read-only; long values are visually truncated and attachments/local-only metadata are not displayed.
